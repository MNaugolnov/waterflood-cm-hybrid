# Веб-интерфейс к модели CM + ХВ + нейросеть

Одностраничное приложение на Dash (тёмная панель по образцу проекта Velebit): слева — данные и
фильтры, справа — вкладки с картой связей, прогнозом, откликом на закачку и сценарием
перераспределения. Расчёты выполняет пакет `hybrid` из соседней папки `crm_hybrid_model`.

## Запуск

```
pip install -r requirements.txt
python app.py
```

или двойной щелчок по `run.bat`. Откроется http://127.0.0.1:8050 (порт меняется в `config.py`).

Папка `crm_hybrid_model` должна лежать рядом с `crm_webapp`. Если она в другом месте — укажите
путь в `config.py` (`HYBRID_PATH`) или в переменной окружения `CRM_HYBRID_PATH`.

## Входные данные

Три таблицы: CSV/TXT (разделитель `;`, `,` или табуляция; UTF-8 или Windows-1251; десятичная
точка или запятая) либо Excel. Столбцы распознаются по названиям, порядок любой.

| Файл | Обязательные столбцы | Распознаваемые названия |
|---|---|---|
| Добыча | скважина, дата, дебит жидкости (м³/сут), обводнённость (%) | `Well_ID`, `Скважина`, `Номер скважины`; `Date`, `Дата`; `Qliq`, `Qж`, `Дебит жидкости`; `WC`, `%`, `Обводненность` |
| Закачка | скважина, дата, приёмистость (м³/сут) | `Qinj`, `Приемистость`, `Закачка` |
| Координаты | скважина, X, Y (м) | `X`, `Y`, `Координата X` |

- Вместо обводнённости можно дать дебит нефти (`Qoil`, `Qн`); если он в т/сут, пересчёт идёт
  через плотность `OIL_DENSITY` из `config.py`. Без обводнённости и нефти работают только
  расчёты по жидкости.
- По желанию — забойное давление (`BHP`, `Рзаб`).
- Закачку можно дать «широкой» таблицей: первый столбец — дата, остальные — скважины.
- Если закачка лежит в том же файле, что и добыча (выгрузка вида `BlockN.csv` со столбцами
  «Характер работы» и «Приемистость»), файл закачки не нужен.
- Даты: `31.12.2019`, `2019-12-31`, `12/31/2019`.
- Запись есть только тогда, когда скважина работала. Пропуск записей дольше 14 суток (для
  месячных данных — 45) считается остановкой.
- Шаг расчёта определяется по данным: 7 суток для суточных замеров, 30 — для месячных.
- В расчёт входят скважины с координатами и не менее 26 шагов работы (12 — для месячных).

Пример трёх файлов — в `sample_data`: это синтетический участок, его создаёт
`crm_hybrid_model/make_synthetic.py`. Участки из `crm_hybrid_model/data` (подпапки `Block N`)
тоже доступны в списке «Источник».

## Вкладки

**Карта связей.** Скважины по координатам, линии «нагнетательная → добывающая». Коэффициент на
выбор: `g` — отклик, калиброванный по фактическим изменениям закачки (м³/сут жидкости на
1 м³/сут закачки), или `f` — доли закачки по CM. Ползунки — порог коэффициента и расстояние.
Щелчок по скважине или список слева оставляют только её связи. Ниже — динамика жидкости,
нефти и закачки.

**Прогноз.** Проверка на истории (модели видят только данные до выбранной даты; закачка и
график работы на прогнозном периоде фактические) или прогноз вперёд от конца истории (закачка
и график работы заморожены на последнем уровне). Жидкость: инерционный прогноз, CM, по желанию
гибрид с нейросетевой поправкой. Нефть: характеристики вытеснения поверх прогноза жидкости.
Суммы и ошибки считаются по базовому фонду — скважинам, работавшим на дату прогноза.

**Отклик на закачку.** Резкие изменения приёмистости на участке и фактическое изменение дебита
соседей после них, с 95 %-ми интервалами, рядом — отклик по CM и по модели отклика. Таблица
нагнетательных с коэффициентами.

**Сценарий.** Перенос закачки между скважинами вручную или автоподбор при неизменной суммарной
закачке (каждая скважина меняется не больше чем на заданный процент). Результат — изменение
жидкости и нефти участка во времени и по скважинам, для сравнения — оценка CM без калибровки.

## Что важно знать о результатах

- CM без калибровки завышает отклик на изменение закачки в 2–3 раза (проверено на 647 событиях
  5 участков), поэтому сценарии считаются по модели отклика, а `f` показаны для справки.
- Коэффициенты модели отклика по умолчанию получены на тех же 5 реальных участках (τ = 60 сут,
  G_geo = 0,052, G_f = 0,175). Для другого месторождения включите «калибровать отклик по этим
  данным»; если наблюдений мало (меньше 500), приложение оставит значения по умолчанию и скажет
  об этом. Калибровка работает только для шага 7 суток.
- Изменение нефти в сценарии = изменение жидкости × текущая доля нефти скважины. Прямой отклик
  по нефти на проверке статистически не подтверждён — это оценка порядка величины.
- Автоподбор — линейная задача без ограничений по давлению, приёмистости и риску прорыва воды.
- На одном участке событийная оценка шумная: интервалы широкие, это нормально.
- Месячные данные поддерживаются, но точность моделей проверялась только на суточных замерах.

## Время расчёта (ориентиры)

| Действие | 20–50 скважин | ~150 скважин |
|---|---|---|
| Загрузка и настройка CM | 3–5 с | 20–30 с |
| Прогноз с ХВ | 15–20 с | около минуты |
| Нейросетевая поправка | около минуты | несколько минут |
| Отклик, сценарий | до секунды | 1–2 с |

Подбор ХВ идёт в нескольких процессах (`JOBS` в `config.py`; `1` — отключить).

## Состав папки

| Файл | Назначение |
|---|---|
| `app.py` | разметка страницы и обработчики Dash |
| `core/reader.py` | чтение и распознавание входных таблиц |
| `core/engine.py` | расчёты: настройка, связи, прогноз, отклик, сценарий |
| `core/figures.py` | графики (словари Plotly) |
| `assets/style.css` | оформление |
| `config.py` | пути, порт, параметры |
| `sample_data/` | пример входных файлов |
| `tests/test_core.py` | проверка чтения данных и расчётов: `python tests/test_core.py` |

## Как проверялось

Расчётное ядро и чтение данных проверены тестами (`tests/test_core.py`: форматы файлов,
полный расчёт, месячные данные) и прогонами на трёх реальных участках (в репозиторий не входят)
и на синтетическом. Обработчики интерфейса
проверены прогоном всех сценариев работы (загрузка, выбор скважин, прогноз, отклик, сценарии,
ошибочные данные) на программной имитации Dash. В настоящем браузере с установленным Dash
приложение при подготовке не запускалось: в среде разработки не было Dash и Plotly. Если при
первом запуске что-то выглядит или работает не так — это нужно поправить по факту.
